Related files

–app/auth/routes.py login and logout. No reset route.

–app/models/user.py no token fields.

How the current code works

Login checks the bcrypt hash, then makes a 60-minute JWT with make_access_token(). There is no reset flow, so POST /auth/forgot is a 404 (matches the staging log). Email is sent sync from the request.

Risks

–User enumeration if known and unknown emails answer differently.
–Timing leak if tokens are compared with ==.
–app/auth/limit.py uses naive datetime.utcnow(). Mixing it with aware times breaks expiry checks.
–No Redis in docker-compose.yml. Do not plan on it.

Suggested approach

1Table password_reset_tokens + Alembic migration.
2POST /auth/password-reset always 202; email via send_mail.
3/confirm: hmac.compare_digest, expiry, single use.
4RESET_TOKEN_TTL_MINUTES = 30 in settings. Tests for expiry, reuse, unknown email.
