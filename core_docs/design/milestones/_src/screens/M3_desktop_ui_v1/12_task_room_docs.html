Plan - Add password reset API

Goal

Let a user reset a forgotten password by email. One-time link, valid for 30 minutes. The same 202 answer for known and unknown emails, so nobody can find out which emails have an account.

Steps

1.Token model. Add app/models/reset_token.py: user_id, token_hash (SHA-256, never the raw token), expires_at, used_at.
2.Migration. alembic/versions/0042_password_reset_tokens.py creates the table with an index on token_hash.
3.Mail. Add send_reset_email(user, link) to app/services/mail.py, with a plain-text template.
4.Routes. In app/api/auth.py:
–POST /auth/password-reset makes a token, sends the mail, always returns 202.
–POST /auth/password-reset/confirm checks the token, sets the password, returns 410 if used or expired.
5.Tests. tests/api/test_password_reset.py: happy path, expired, used twice, unknown email.

Risks

–Open question: tokens in a new table or in Redis? The brief does not say. I assume a table; ask before step 2.
–Compare tokens with hmac.compare_digest, not ==.
–Rate limit the request route, or it can be used to spam a mailbox.

Tests

uv run pytest tests/api/test_password_reset.py -q
uv run alembic upgrade head && uv run alembic downgrade -1
